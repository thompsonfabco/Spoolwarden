# Spoolwarden 0.6.8

Upgrade the Hub with `sudo spoolwarden update`.

The first release since 0.6.3, which changed only the Tag Reader. This one adds a first-run path (Guided Setup and Getting
started), storage locations, alerts, checked-out spools, a Spools section, a live printer view and Analytics on the Hub
page, voice settings and an optional Wi-Fi link for the Weigh Station's panel. The command is now `spoolwarden`. Some
things the pages already show do not work yet: see "Not in this version yet" at the end.

## After updating

These apply whether you come from 0.6.3 or from 0.6.2. From 0.6.2 you also get what 0.6.3 changed for the Tag Reader; read
the 0.6.3 notes for that.

- **Your Hub keeps its port.** An update never moves a Hub. A Hub that is installed already keeps the port it has (8710 for
  almost every Hub), and so do its phones, Slicer Sync and the addresses you use: `https://my-server.local:8710/setup` keeps
  working. Only a new install takes port 443. If the `ufw` firewall is on, the installer prints the line that opens the
  Hub's port, for example `sudo ufw allow 443/tcp`; it does not change the firewall.
- **The command is `spoolwarden`.** Install and update put `spoolwarden` where `filament-kit` was. `filament-kit` still
  works for a time: it runs `spoolwarden` with the same arguments, input, output and exit code, and prints one line on
  standard error saying the name changed. `spoolwarden --version` prints `Spoolwarden <version>`.
- **Your storage settings become a list.** The first time the Hub starts, it builds the list of storage locations from
  your old settings, so every new spool is placed where it was before; spools already stored keep their place. The old
  settings stay in the configuration file and are no longer read. If one name had two jobs, the Hub page and `sudo
  spoolwarden locations` say **Storage locations were converted. Check them.** Look at the list and save it, and the
  notice goes. Details are under "Spools" below.
- **Going back.** `sudo spoolwarden update --rollback` returns to the previous release, which reads its old settings
  again. Changes you made to the storage locations do not go back with it. The Hub keeps its settings and records in the
  new form and the older form side by side for one release, so the older release finds them.
- **Paired phones, Slicer Sync and Weigh Stations stay paired.** The port does not change, so nothing needs pairing again.
  That changes only if you move the Hub to another port yourself (see "First run").
- **A Tag Reader set up before is not changed.** It keeps working as it did. It changes only when you set it up again over
  USB, on the Hub page under **Flash a device** or with `sudo spoolwarden tag-reader flash`. Set a reader up again also
  after you move the Hub to another port or make a new certificate for it.
- **The Weigh Station answers over HTTPS after it is updated.** If the Weigh Station runs on another computer, update
  that one too. A paired Weigh Station tells the Hub its certificate each time it starts, so you do nothing more. A Weigh
  Station that is not updated yet tells the Hub no certificate, and the Hub keeps calling it over plain HTTP as before.
- **The Weigh Station's panel may get new firmware.** The Weigh Station writes the firmware it carries (version 14) to the
  panel over USB, once per version, unless `"panel_flash"` is `false`. A panel on firmware 13 or older gets the whole
  image. The panel stays on its USB cable until you run `sudo spoolwarden weigh-station panel-wifi`.
- **A Klipper printer's tag service can be updated.** If you installed the Klipper add-on's tag service before, running
  the add-on's installer again offers to update it so that it answers over HTTPS. It asks first and restarts the service.
  See "Printers" below.

## First run

- **Guided Setup.** A first install at a Terminal now begins with **Finish setting up in your browser (Guided Setup)?**
  Yes installs the Hub with the usual choices, asks nothing more and ends with the Hub's address and the setup code. No
  asks the questions in the Terminal, as before, and is the way to install only a Weigh Station. Giving an option such as
  `--mode` skips the question.
- **Getting started.** On the Hub page the Overview shows a **Getting started** list until every item is done or you
  choose **Hide this list**. Its items include: name the Hub, check the storage locations, choose features, install the
  Label Reader, set the Anthropic API key, add a printer, map its slots, use a phone, set the web passphrase, pair Slicer
  Sync, add your first spool and make a first backup. It has **Restore a backup** for a Hub that moves from another
  computer. `spoolwarden status` shows the same list at the top while items remain.
- **A new Hub is on port 443**, so its address has no port: `https://my-server.local/setup` instead of
  `https://my-server.local:8710/setup`. If 443 is in use, the installer asks for another port at a Terminal and offers
  8710; without a Terminal, or with Guided Setup, it takes 8710 and says so. Remote access needs 443 for itself, so on a
  Hub that holds 443 switching it on stops with "Remote access needs port 443, and the Hub is using it."
- **Typed addresses need no port.** The app (Android) and Slicer Sync try 443 and then 8710, and use the one where a Hub
  answers. Leave **Port** empty when you pair.
- **Move the Hub to another port.** On the Hub page, **Settings**, **Network and addresses**, **Hub port**, **Change port**,
  or `sudo spoolwarden port <number>` (443, or 1024 to 65535). Afterwards pair your phones and the Slicer Sync PC again if
  they do not find the Hub; a Weigh Station on another computer must be paired again, and Tag Readers set up for this Hub
  must be set up again.
- **A new certificate.** `sudo spoolwarden certificate --renew` makes a new certificate for the Hub and restarts it. Every
  paired phone, PC and Weigh Station sees a changed certificate and must trust it again or be paired again, and Tag
  Readers set up for this Hub must be set up again. It asks first.
- **A Label Reader on another computer.** An `http://` address works as before. For an `https://` address the Hub keeps the
  reader's certificate from the first time it reaches the reader and accepts no other from that address.
- **Flash a device warns early.** If the Hub's certificate has no `.local` name, the Hub page's **Flash a device** now says
  so before you start, not when setup stops.

## Spools

- **A Spools section** on the Hub page lists your spools, with chips for **Checked out** and **Running low**. The web app
  and the app (Android) have the same two chips in their spool search.
- **Checked-out spools.** A spool loaded into a printer slot is checked out until it is returned. The Hub remembers its
  **Home**, the place it came from, and since when. **Return** sends it back to its home, or, when no home is recorded, to
  the place the storage rules choose, and offers **Undo**. **Change home** changes where it will go back to. On the Hub
  page, in the web app and in the app (Android), a checked-out spool shows its home and **Return**. At a Terminal,
  `spoolwarden spools --checked-out` lists them, `spoolwarden spool return <n>` returns one and `spoolwarden spool home <n>
  <location>` changes its home. When the spool sat in a Klipper printer's slot, the Hub also tells the printer to
  clear that slot, if the printer answers; it says so when it could not.
- **Storage locations.** Where your spools are kept is now one ordered list of locations that you edit, instead of five
  fixed settings. Each has a name and a type: **Bulk storage** (a shelf, rack or drawer, with an optional spool limit) or
  **Individual containers** (boxes or bags that hold one spool each; the Hub numbers them, for example `Dry box 01`). Each
  is filled automatically with nothing, any material or the materials you name, and can be overflow. One overflow location
  is the default overflow, and one Bulk storage location takes the sealed spools.
- **Where a new spool goes.** A spool you add without a location goes to the sealed location while it is still sealed.
  Otherwise it goes to the first place for its material that has room, then to the first place that takes any material,
  then to an overflow location. With PLA rack 1 limited to 20 spools and PLA rack 2 behind it, the 21st PLA spool goes to
  rack 2. Choosing a place by hand still works when it is full.
- **Where to edit it.** On the Hub page, **Settings**, **Storage locations**: add, edit, reorder and remove locations, mark
  the default overflow and the sealed location, and see where a new spool of each material would go before you save.
  Renaming a location renames it on the spools stored there. At a Terminal, `sudo spoolwarden locations` lists the list
  and has `add`, `edit`, `move`, `remove`, `default-overflow` and `sealed`; `sudo spoolwarden config` has the same screen,
  and `config set` no longer takes the old settings.
- **In the apps.** The web app and the app (Android) show how full each place is in the **Location** choice and in
  **Move**, mark a full place as **Full** (it can still be chosen), and after a preview say where a spool on
  **Automatic** would go and why. The list itself is edited on the Hub page or at a Terminal.
- **When Spoolman cannot be reached.** The list of storage locations still shows, from the Hub's own settings, and the
  counts read **Unknown** instead of 0: on the Hub page, in the web app and in `sudo spoolwarden locations`, which adds
  that the Hub cannot reach Spoolman. Saving or previewing a change that needs Spoolman is still refused.

## Printers

- **A live printer view** on the Hub page, in **Printers**: the printer's state, its camera, pause, resume and stop (stop
  asks first), the light, the filament in each slot with **Load into slot**, **Unload slot** and **Clear slot**, and its
  filament used. It asks for the setup code or a trusted computer before it acts.
- **Load a spool into "Automatic".** Choose **Automatic** for the slot and the Hub waits up to 15 minutes for the slot where
  the spool appears, then loads it there. If two slots are loaded meanwhile it asks which one got the spool, and **Stop
  waiting** ends the wait. It works on the Hub page, in the web app and in the app (Android). The Hub does not keep the wait
  if it restarts.
- **Klipper: the tag service answers over HTTPS.** The `lasttag` service of the Klipper add-on, which the Hub reads taps
  from, now serves HTTPS with a certificate of its own. The add-on's installer offers port 443 when it is free (else 5002)
  and offers to update an older install. The Hub keeps the certificate it meets the first time it reads that address and
  accepts no other from it; **Save the tag source again to trust the new certificate** if you replace it. A tag service on
  another computer that answers only over plain HTTP is still read, and the Checks say "The tag service at <address> is not
  using HTTPS. Update it."
- **Klipper: alerts and Return.** The Hub watches Klipper printers as well as Bambu Lab ones for alerts (see "Alerts"), and
  a spool returned from a Klipper printer's slot is cleared on the printer too, as described under "Spools".

## Alerts

- **What is written down.** The Hub writes down what happens: a print starts, pauses, runs out of filament, fails or
  finishes; a printer reports an error; a spool is added, moved or runs low; the Hub's disk fills; a device stops
  answering. It turns the kinds you want into alerts. Eight kinds exist: **Filament ran out**, **Print paused**,
  **Print failed or stopped**, **Printer error**, **Storage almost full** and **Spool running low** are on at the start;
  **Print finished** and **Device stopped answering** are off.
- **Where they show.** The web app, the app (Android) and the Hub page show an alert as a banner at the top (at most two,
  then **<n> more alerts**), with a button to the place that deals with it and **Dismiss**. **Recent alerts** lists what is
  happening now and the alerts of the last 7 days: in the web app under **More**, **Settings**; in the app (Android)
  under **Settings**, **Alerts**; on the Hub page under **Settings**, **Alerts**.
- **Choose them on the Hub page.** **Settings**, **Alerts** has the eight switches, a switch to limit **Spool running low**
  to the last spool of a filament, **Running low under** (150 g to start with) and **Storage warning at** (85 % used to
  start with); **Save alerts** saves them with the setup code. The apps show these but do not change them. At a Terminal:
  `spoolwarden alerts`, `sudo spoolwarden alerts set <type> on|off`, `alerts set running-low <grams>`,
  `alerts set storage-warning <percent>` and `sudo spoolwarden alerts test`.
- **Notifications.** On the Hub page, **Notifications in this browser** (off until you turn it on) shows each new alert as
  a notification while a Hub page tab is open in that browser. In the app (Android), **Settings**, **Alerts**, **Alerts on
  this phone** (off until you turn it on) notifies you with the app closed, with Android's small permanent notification
  **Watching the Hub for alerts**; it works only while the phone can reach the Hub. In the web app, notifications with the
  app closed use Web Push, which is off until you set `"web": {"push": true}`. **Send a test alert** is on each of these
  pages.
- **Running low and storage.** An opened spool at or under 150 g is running low; the last spool of a filament is marked
  **Last one**. `sudo spoolwarden spools low` lists them. The Hub's disk is warned about at 85 % used and counts as full at
  95 % used or under 1 GB free. On the Hub page the Overview has a **Running low** card, and a Storage row that needs a
  look has **Show storage use**, which opens **Storage use**: the disks and the space the Hub's backups, photos, events
  and logs take. `spoolwarden status` shows the disk too.
- **The event list.** `spoolwarden events [--since ID|TIME] [--kind PREFIX] [--follow]` lists what the Hub wrote down.

## History and data

- **Activity and Undo.** On the Hub page, **Logs**, **Activity** lists what was done on the Hub, and a row that can be
  undone has **Undo**. The web app and the app (Android) show **Undo** after a change. A weighing, move, empty, open, load,
  unload, return or cleared slot can be undone within 7 days, once, and only while it has not changed since.
  `spoolwarden activity [--spool N] [--who WHO] [--days N]` lists, and `sudo spoolwarden undo [<event id>]` undoes.
- **Analytics.** The Hub page has an **Analytics** section: **Filament used per month**, filament used by material and
  highlights. The Overview shows **Filament used this month**. The web app and the app (Android) show a printer's usage
  by month, and `spoolwarden usage --by month [--printer PRINTER]` prints it.
- **CSV.** Lists on the Hub page have **Download as CSV**. At a Terminal `sudo spoolwarden export <dataset>` writes one
  (`usage`, `locations`, `recent`, `activity`, `printers`, `lines`, `spoolman-spools` or `spoolman-filaments`), and `sudo
  spoolwarden import spools|locations <file>` reads spools or locations from CSV, showing what it will do and asking first.
- **A backup password.** On the Hub page, **Settings**, **Backups**, **Set a backup password** (at least 10 characters)
  encrypts every new backup; backups made that way are marked **Encrypted**, and restoring one asks for its password. Write
  the password down: the Hub cannot recover it. At a Terminal: `sudo spoolwarden backup password [--remove|--show]`, and
  `restore --password-file`.
- **A Hub report.** On the Hub page, **Logs**, **Collect a Hub report**, or `sudo spoolwarden report [--out FILE]`, saves a
  report you can send when you ask for help.

## The Weigh Station

- **Voice settings.** On the Hub page, **Settings**, **Weigh Station voice** has **Speak**, the **Voice**, **Speaker**,
  **Speed**, **Volume** and **Test**. Each applies when you let go of it; there is no Save, and the Weigh Station restarts
  when the voice changes. The web app (at home) and the app (Android) have the same panel under **Settings**; there the
  voice itself is read-only. `sudo spoolwarden weigh-station voice-test` plays the test sentence, and `sudo spoolwarden
  config` has the same group.
- **Plastic types are spelled out.** The Weigh Station now says a material letter by letter: "PLA" is spoken "P L A" and
  "PA6-CF" "P A 6, C F". HIPS, PEEK and names with small letters ("Silk", "Nylon") are said as words. The screen still
  shows "PLA".
- **Returning a checked-out spool.** Scan its tag and the display reads **Returning** with its name and **Home**. A short
  press of yellow weighs it, then hold yellow to save and return it; hold yellow at once to return it without weighing. It
  says where it went, for example "Returned to Rack 1."
- **The panel over Wi-Fi (optional, off, and not yet tried on a real panel).** Plug the panel into the Weigh Station's
  computer by USB once and run `sudo spoolwarden weigh-station panel-wifi`; it asks for the Wi-Fi name and password, and
  the panel then only needs power. It needs the panel's firmware 14. `sudo spoolwarden weigh-station panel-wifi --off` goes
  back to the cable. Until you run it the panel talks only over USB. It is covered by automated tests only: whether the panel
  keeps its link while it speaks is not confirmed.
- **HTTPS.** The Weigh Station makes a certificate of its own at its first start and answers only over HTTPS. A changed
  certificate is refused by the Hub, never replaced by plain HTTP. A first install of a Weigh Station on a computer of its
  own takes port 443 when that is free; otherwise the installer at a Terminal asks `Port for the Weigh Station [5003]:`.

## Fixes

- **The storage list while Spoolman restarts.** The Hub page, the web app and the command line no longer fail with "The Hub
  can't reach Spoolman right now" while Spoolman restarts; see "Spools".
- **Flash a device warns about a missing `.local` name** before you start (see "First run").
- **`tag-reader flash --printer`** with a printer that is not one of the Hub's now ends with a usage error (exit code 2).
- **A Ctrl-C ends the `sudo spoolwarden config` menu** even when it lands just before the menu waits for a key.
- **A refusal always reaches the caller.** When the Weigh Station refuses a request, the Hub page, an app or a paired
  device now always gets the refusal as its answer; before, the connection could just drop.

## Not in this version yet

Some things that the pages and apps already show, or that another place already does, cannot be done yet. The most visible:
the web app and the app (Android) cannot clear a printer's slot (use **Clear slot** on the Hub page), the command line cannot
load or unload a printer's slot, spool labels are not served, the demo cannot be switched on, and Language offers only
English. The panel over Wi-Fi has not been tried on a real panel. The full list is in
[docs/known-gaps.md](../docs/known-gaps.md), from entry 23.
