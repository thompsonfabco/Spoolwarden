# Spoolwarden 0.6.3

Upgrade the Hub with `sudo spoolwarden update`.

A release of fixes for the Tag Reader and its setup. Nothing else changed.

## After updating

A Tag Reader that was set up before is not changed by the update. It was built to keep calling the public address it
was given, through Remote access; this release was not tested with such a reader.
It gets the fix only when you set it up again over USB: on the Hub page open **Flash a device**, or plug the reader into
the Hub and run `sudo spoolwarden tag-reader flash`. Setup always writes new settings. Done on the Hub over USB or from
the command line, it writes the Hub's newer firmware when the board runs an older build; the Hub page's **This
computer** way writes the firmware every time.

Setting a reader up now needs a `.local` name in the Hub's certificate. If it has none, setup stops with "The Hub's
certificate has no .local name, so a Tag Reader could not check it. The certificate is made once, when the Hub is
installed, and this version has no command that renews it."

## Fixed

### Tag Reader

- **The Tag Reader talks to the Hub on the home network only.** In 0.6.2 it could reach the Hub only through the Hub's
  public address. A reader set up now calls the Hub at its own address, `https://<Hub name>.local:<port>/reader`, and
  checks the Hub's own certificate. The new firmware is made to look the name up on the network for up to 2 seconds,
  and, if that finds nothing, to use the Hub's home IP address from setup (for example `192.0.2.10`). It needs no
  public address and no Remote access.
  The Hub page's **Flash a device** no longer refuses to start when the public address is not set.
- **The setup says which of the two failed, the Wi-Fi or the Hub.** In 0.6.2 a reader that had joined the Wi-Fi but
  could not reach the Hub was reported as not joining the Wi-Fi. The new firmware is made to report the Wi-Fi result as
  soon as it knows it, then the Hub result; the Hub page ignores a report that is cut short. On the Hub page the
  results read:
  - "The Tag Reader could not join '<Wi-Fi>'. Check the Wi-Fi name and password (2.4 GHz networks only)."
  - "The Tag Reader joined the Wi-Fi but could not reach the Hub at <address>. Check that the Tag Reader's Wi-Fi is the
    Hub's home network." (In 0.6.2 this one told you to check the public address.)
  - "The reader did not answer in time. Run this again." (This replaces "The board did not report back. Run this
    again.")
- **The printer the reader starts on can be chosen when it is flashed.** The Hub page's **Flash a device** has a
  **Printer** field ("The printer the Tag Reader starts on. The knob can still change it."). Its choices are **Choose
  on the reader**, which is the default and works as before, and each printer of the Hub, Bambu Lab and Klipper. On the
  command line add `--printer PRINTER` to `spoolwarden tag-reader flash`; `-h` prints it as "the printer id the reader
  starts on (the knob can change it); left out, it is chosen on the reader". A printer that is not one of the Hub's is
  refused with "That printer is not one of this Hub's printers."
- **The buzzer choice is worded "Bare buzzer" and "Buzzer with driver board".** They replace "High-triggered (the build
  in the parts list)" and "Older 3-pin module", on the Hub page and in the command's question and its `--buzzer` help.
  Bare buzzer is the same as the old high choice and the default; Buzzer with driver board is the same as the old low
  choice. The command still takes `--buzzer high` and `--buzzer low`.

### The Hub page

- **Settings > Network and addresses shows the public address.** In 0.6.2 the field showed "Set (hidden). Type a new
  address to replace it." and now holds the address itself, so you can read it and edit it.

## What did not change

The Weigh Station, the printers, the phone web app and the Android app are as in 0.6.2.

## Upgrading

Run `sudo spoolwarden update` on the Hub. Afterwards `spoolwarden --version` prints `Spoolwarden 0.6.3`. Your spools,
settings, key and paired phones stay. Going back (`sudo spoolwarden update --rollback`) returns to the previous
release. A Tag Reader that was set up under 0.6.3 can no longer reach the Hub after going back to 0.6.2, because 0.6.2
does not answer the reader's calls. Set the reader up again under 0.6.2, which needs a public address.
