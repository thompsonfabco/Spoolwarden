# Spoolwarden 0.6.9

Upgrade the Hub with `sudo spoolwarden update`.

A small release after 0.6.8. It adds a Share corrections switch and a waiting list on the Hub page, a CSV import on the
Hub page, a By month view and a CSV range choice for printer usage, a Return line when the printer could not be told,
and a Tag Reader firmware update. The Android app now reads its texts from the shared catalogue and asks for a spool's
newest events. Nothing here needs a step from you beyond the update.

## Not run before this release

Not run before this release: the test suites, Android unit tests, the reader and panel board builds' tests, and any
device. The Antigravity changes were not reviewed.

## Tag Reader

Tag Reader firmware build 1795334117: longer Wi-Fi and Hub timeouts, a repeated reach check during setup, no beep on reconnect.
Not tested on a device before release; to go back, flash the 0.6.8 image.

The reader also logs the TLS result, the address it reached and the Wi-Fi signal strength. A Tag Reader set up before is
not changed: it takes the new image only when you flash it again, on the Hub page under **Flash a device** or with
`sudo spoolwarden tag-reader flash`.

## Share corrections

- **A switch and a list on the Hub page.** Under Settings > Label Reader, **Share corrections** turns on keeping each
  correction you make to a reading, so it waits on the Hub. **Corrections waiting** lists them with their photos, what
  was read, what you changed it to and your note. Nothing is sent until you press **Send now**. You can remove one or
  all, and download the package that Send now sends to look at it first.
- **Turning it off asks what to do** with the corrections still waiting: keep them to send later, or delete them. Turning
  off the Label Reader on this Hub in Features warns when that would delete corrections waiting.
- **Recently added** shows whether a correction is waiting, was not taken, or has no photo kept.
- **The Android app** has a Corrections waiting page with the same list. Sending is done on the Hub page.
- **The command line** asks before deleting waiting corrections and says how many were kept.

## Hub page

- **Import from CSV.** Spools and storage locations can be imported from a CSV file, with a sample file to download, a
  check that shows what would be added and which rows have problems, and then the import. Files that are too large are
  refused before they are read. A container whose name matches one in the same set shows a warning.
- **Printers.** The guided add lists the Bambu Lab printers it found. The printer usage CSV has a range choice of 7 days,
  30 days or 12 months.
- **Updates.** The Updates tab shows when a newer Label Reader is available and has an **Update Label Reader** control.
  The command line has the same as `sudo spoolwarden local-intake update`.
- **Devices.** An **Open** link sits beside each web app address.
- **Label history.** Small label photos are served as bounded thumbnails and cached by the browser.
- **Storage.** When Spoolman cannot be reached, the Hub page, the command line and the app say the spool counts are
  unknown instead of showing zero. The `locations add`, `edit`, `move` and `remove` commands refuse to run then.
- **Slow answers.** A Hub page request that gets no answer within 30 seconds now says so.

## Recent and the web app

- **Recent** has a **To check** filter and confidence lines, the install label follows what the browser offers, and
  Printers shows a warning badge.
- **Filament used** on Printers shows By month as bars from tablet width, has a CSV range menu, and the toggle says
  **Last 7 days**. The table can be hidden.
- **Hub down.** The web app treats an answer of 502, 503 or 504 from the Hub as the Hub being offline, and waits up to
  30 seconds before giving up on a request.
- **Return** says **The printer could not be told to clear its slot.** when the printer was not told. The same line
  shows on the Hub page, the command line and in the Android app. The Hub's record still changes.
- Pressing **Send now** keeps the keyboard focus where it was, and alert polling no longer stacks up requests.

## Android app

- The app asks a spool's events with `newest`, and calls the kit routes the Hub documents.
- Storage counts show **Unknown** when the Hub says it cannot count.
- Its texts come from the shared catalogue, with some words changed to match the Hub page and the web app. Six texts
  the Hub's web fallbacks also use are renamed with an `app_` prefix so they no longer shadow each other.

## Command line and pairing

- New and changed commands and rows in the help table: `local-intake update`, demo stops, and the Share corrections
  prompts. `spoolwarden --help` lists them.
- Pairing a device now returns its role, the Hub's `hub_id` is in the info answer, and `pair` prints the Hub's address.
  The address a phone is told prefers the default-route address of the Hub and skips bridge interfaces.
- **The demo** answers 409 when it cannot be switched on, with a text for it: "The demo cannot be switched on in this
  version."

## Names and texts

- Unit descriptions, backup messages and the installer's once-only rename line use the new name. `install.sh` also
  prints the rename line with `--restore`.
- The user guide has the command table, the checked-out spools, voice settings and the panel over Wi-Fi, and the known
  gaps are renumbered. It does not yet describe Share corrections, CSV import, `local-intake update` or the Unknown
  storage counts.

## Not in this version yet

- Anything listed under "Not in this version yet" in the 0.6.8 notes is still not done.
